# Приймач пропозицій (необов'язково)

`submit.php` приймає пропозиції зі сторінки і дописує їх у приватний файл. Сторінка працює і без нього: тоді кнопка «Надіслати» відкриває готовий issue на GitHub.

## Розгортання

1. Покласти `submit.php` на PHP-хостинг (7.4+). Дані пишуться **поза webroot**: `<на рівень вище DOCUMENT_ROOT>/private_data/` (або `SUBMISSIONS_DIR`).
2. У `private_data/config.json` (не в репозиторії):
   ```json
   {"telegram_token": "<токен бота>", "telegram_chat": "<id чату>", "notify_threshold": 20}
   ```
   Без токена сповіщень нема, лише збір.
3. У репозиторії в `config.json` вказати `"submit_url": "https://<хост>/submit.php"` і запушити: сторінка перебудується сама.

## Що зберігається

`submissions.jsonl`: час, Spotify ID, необов'язкова нотатка (до 300 символів, без HTML) і перші 12 символів SHA-256 від адреси з випадковою сіллю. Самі адреси не зберігаються. Ліміт: 20 пропозицій на годину з однієї адреси, до 20 виконавців у пропозиції. CORS дозволений лише для `https://rafttone.github.io`.

## Сповіщення

Після кожної пропозиції приймач додає нових унікальних виконавців у чергу. Коли їх набирається `notify_threshold` (20 за замовчуванням), надсилає одне повідомлення в Telegram і чистить чергу. Якщо Telegram не відповів, черга лишається і повідомлення повториться при наступній пропозиції. Той самий виконавець, запропонований повторно, у чергу вдруге не потрапляє.

## Перегляд

```
python3 tools/review.py submissions.jsonl
python3 tools/review.py submissions.jsonl --approve <ID> <ID> ...
```
Таблиця показує ім'я, країну з MusicBrainz, скільки разів пропонували і чи вже є в списках; українців (UA) позначено «УВАГА».
